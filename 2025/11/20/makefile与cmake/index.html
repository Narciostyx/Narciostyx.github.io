C/C++ make与cmake

C/C++ 项目构建工具 make 与 cmake 的使用指南

makefile

  • linux 下使用 make 命令构建，make 会查找当前工作目录下的 makefile 文件（GNU make 的查找顺序为 GNUmakefile → makefile → Makefile，取第一个找到的）
  • makefile 的基本单元是规则：目标（target）、依赖（prerequisites）、命令（recipe）
  • make 不会自动发现依赖，依赖必须显式写出；make 通过比较目标与依赖的时间戳判断是否需要重新执行命令（依赖比目标新 → 执行），从而实现增量构建

    • $^，所有依赖（去重后）
    • $<，第一个依赖
    • $?，比目标新的依赖
  • 预定义变量：CC（默认 cc）、CXX（默认 g++）、CFLAGS、CXXFLAGS、LDFLAGS 等。C 项目用 $(CC) $(CFLAGS)，C++ 项目用 $(CXX) $(CXXFLAGS)

  • 伪目标（phony target）：用 .PHONY 声明该名字不对应任何真实文件，make 总是认为它需要执行；即使当前目录恰好存在同名文件（比如一个叫 clean 的文件）也会照常执行。只有执行 make <名字> 时才会触发：
  • 命令的执行方式：每条命令默认在独立的 shell 中执行；同一行内用 ; 或 && 连接才能保证在同一 shell 中按顺序执行，如 echo "xxx"; g++ hello.cpp -o hello; echo "xxx"（&& 表示前一条成功才执行后一条）
  • make 常用参数：
    • make -j8，并行构建（同时跑 8 个任务）
    • make -n，只打印将要执行的命令，不真正执行（调试用）
    • make -B，强制全部重建（忽略时间戳）
    • make -f mymakefile，指定 makefile 文件名
    • make -C dir，先进入 dir 目录再执行 make
    • make target，只构建指定目标，如 make clean
    • 命令行覆盖变量：make CXXFLAGS="-O2" 会覆盖 makefile 中的赋值
  • 常用写法补充：
    • 模式规则（pattern rule）：%.o: %.cpp 一条规则匹配所有 .cpp → .o 的转换

    • 通配与字符串处理：SRCS = $(wildcard *.cpp) 收集所有 .cpp 文件；$(SRCS:.cpp=.o) 把后缀替换为 .o

cmake

  • 平台无关的跨平台构建系统生成器，使用 CMakeLists.txt 描述构建，可以生成 Makefile、Ninja、Visual Studio 工程（.sln）等
  • 语法
    1. cmake_minimum_required(VERSION 3.16) #最低版本要求，必须放在第一行
    2. project(Demo VERSION 1.0 LANGUAGES CXX) #项目名、版本号、使用的语言
    3. add_executable(Demo main.cpp) #指定生成目标（将 main.cpp 编译成名为 Demo 的可执行文件）
      1. 当同一目录下源文件很多时，可以使用 aux_source_directory(<dir> <variable>) 查找 dir 目录下的所有源文件并把名称保存到 variable 中（旧式写法，CMake 3.27 起已弃用），如 aux_source_directory(. DIR_SRCS)，add_executable(Demo ${DIR_SRCS})；也可以 file(GLOB DIR_SRCS *.cpp)（注意：GLOB 在新增文件后不会自动重新配置，可加 CONFIGURE_DEPENDS）。最稳妥的是显式列出源文件
    4. 当使用 add_subdirectory(<path>) 时，该目录下的 CMakeLists.txt 与源代码也会被包含
    5. add_library(MathFuncs STATIC math/MathFuncs.cpp) #生成库（STATIC 静态库 / SHARED 动态库）
    6. target_link_libraries(Demo PRIVATE MathFuncs) #添加链接库，PRIVATE/PUBLIC/INTERFACE 控制依赖是否传递
    7. target_include_directories(Demo PRIVATE include) #指定头文件搜索路径（现代写法，替代 include_directories）
    8. add_compile_options(-Wall -O2) #给当前目录及以下所有目标增加编译器选项
    9. set(<variable> <value>) #设置变量
    10. find_package(Boost 1.70 REQUIRED) #搜寻指定库；指定查找路径常用 set(OpenCV_DIR /path/to/opencv) 或设置 CMAKE_PREFIX_PATH，找到后通过 target_link_libraries(Demo PRIVATE OpenCV::core) 使用
    11. message(STATUS "xxx") #打印信息，调试配置时常用
  • cmake 常用变量
    • CMAKE_SOURCE_DIR / CMAKE_BINARY_DIR：顶层源码目录 / 顶层构建目录
    • PROJECT_SOURCE_DIR / PROJECT_BINARY_DIR：当前 project 的源码目录 / 构建目录（顶层时与上面两个相同）
    • CMAKE_CURRENT_SOURCE_DIR / CMAKE_CURRENT_BINARY_DIR：当前 CMakeLists.txt 所在目录
    • CMAKE_BUILD_TYPE，构建类型：Debug / Release / RelWithDebInfo / MinSizeRel（只对 Makefile、Ninja 这类单配置生成器生效）
    • CMAKE_CXX_STANDARD，如 set(CMAKE_CXX_STANDARD 20)；或 target_compile_features(Demo PRIVATE cxx_std_20)
    • EXECUTABLE_OUTPUT_PATH / LIBRARY_OUTPUT_PATH，可执行文件 / 库的输出目录（旧式变量；新式写法用 set_target_properties(... PROPERTIES RUNTIME_OUTPUT_DIRECTORY ...)）
    • CMAKE_CXX_FLAGS，C++ 编译器的全局标志（对所有 C++ 目标生效，与只影响当前目录的 add_compile_options 不完全等同）
    • CMAKE_INSTALL_PREFIX，安装前缀，Linux 默认 /usr/local
  • 命令行常用用法
    • 配置：cmake -S . -B build（-S 指定源码目录，-B 指定构建目录；推荐 out-of-source 构建，不要把生成文件写进源码目录）
    • 构建：cmake --build build -j8（自动识别生成器，相当于 make）
    • 安装：cmake --install build（相当于 make install；可加 --prefix 覆盖安装前缀）
    • 选择生成器：cmake -S . -B build -G "Ninja"
    • 传缓存变量：cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
    • 只构建某个目标：cmake --build build --target Demo
    • 清理：cmake --build build --target clean
    • 运行测试：ctest --test-dir build --output-on-failure

自定义编译选项

  • 目的：把 MathFuncs 库设置为一个可选库，即根据配置决定使用该库还是标准库
  • 思路：option() 定义开关 → configure_file() 把 CMake 变量注入头文件模板 → 源文件里用 #ifdef 分支
  • 注意：option() 必须写在 configure_file() 之前，否则变量还没定义，#cmakedefine 会展开成 /* #undef USE_MYMATH */，选项永远不生效；生成的头文件应输出到 ${PROJECT_BINARY_DIR}（构建目录），不要写进源码目录

安装与测试

  • install() 只登记安装规则，配置/构建阶段不会复制任何文件；要执行 cmake --install build（或 make install）才会安装到 CMAKE_INSTALL_PREFIX（Linux 默认 /usr/local）下
  • TARGETS 关键字用于 add_executable / add_library 创建的目标；FILES 关键字必须写真实文件的路径（不能写目标名）
  • 安装的是 libMathFuncs.a（静态库）/ libMathFuncs.so（动态库），不是 .o 文件

gcc 与 g++

区别

  • 两者都是 GNU 编译器套件的驱动程序，底层调用同一个编译器后端（cc1 / cc1plus）
  • g++ 按 C++ 处理源文件（包括 .c 文件），并在链接阶段自动链接 C++ 标准库（libstdc++）
  • gcc 按 C 处理；即使编译 C++ 源文件，链接时也不会自动链接 libstdc++，会出现 undefined reference to 'std::cout' 之类的错误
  • 结论：编译/链接 C 用 gcc，编译/链接 C++ 一律用 g++
  • 注意：gcc -c foo.cpp（只编译不链接）通常能通过，因为没到链接标准库这一步；链接阶段必须用 g++。也可以用 gcc -x c++ foo.cpp -lstdc++ -o foo 强行走 C++ 路径，但没有必要

常用选项速查表：

选项 作用
-o <file> 指定输出文件名
-c 只编译不链接，生成 .o
-std=c++20 / -std=c++17 指定语言标准
-Wall -Wextra 开启常用警告
-g 生成调试信息（配合 gdb）
-O0 / -O1 / -O2 / -O3 / -Os 优化等级
-DNAME=VALUE 定义宏（-DUSE_MYMATH 等价于 #define USE_MYMATH）
-UNAME 取消宏定义
-E 只做预处理，输出到标准输出
-S 生成汇编文件 .s
-v 显示详细编译过程
-fPIC 生成位置无关代码（编译共享库必需）
-shared 生成动态库
-MMD -MP 生成头文件依赖文件 .d（配合 make 自动追踪头文件）
-pthread 链接 pthread（多线程程序）
-fsanitize=address 开启 AddressSanitizer（检测内存错误）
-Wl,-rpath,<dir> 指定运行时动态库搜索路径
