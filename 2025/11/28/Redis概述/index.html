Redis概述

Redis概述

参阅

  • Redis提供高性能的键值存储系统，常用于缓存、消息队列、会话存储等场景：
    • 所有操作均为原子性的
    • 数据持久化
    • 主从复制（节点备份数据或分担请求）

数据类型

  • redis的数据库与MYSQL不同，其更像键的命名空间（逻辑隔离，默认从0-15，通过select切换数据库，连接时默认为0）
  • 通常只使用默认的0号数据库

基础数据类型

  • EX代表过期时间（秒，PX代表毫秒），NX代表当不存在时执行
  • string（字符串）: 基本的数据存储单元，可以存储字符串、整数或者浮点数
  • hash（哈希）:一个键值对集合，可以存储多个字段
  • list（列表）:一个简单的列表，可以存储一系列的字符串元素
  • set（集合）:一个无序集合，可以存储不重复的字符串元素
  • zset(sorted set：有序集合): 类似于集合，但是每个元素都有一个分数（score，double类型分数，从小到大排序）与之关联

拓展数据类型

  • 位图（Bitmaps）：基于字符串类型，可以对每个位进行操作
  • 超日志（HyperLogLogs）：用于基数统计，可以估算集合中的唯一元素数量
  • 地理空间（Geospatial）：用于存储地理位置信息
  • 发布/订阅（Pub/Sub）：一种消息通信模式，允许客户端订阅消息通道，并接收发布到该通道的消息
  • 流（Streams）：用于消息队列和日志存储，支持消息的持久化和时间排序（结构如下，其拥有一个消息链表，将所有消息串起来，且拥有唯一一个ID与其对应（包括内容））
    • Consumer group：消费组，使用xgroup create创建，拥有多个消费者（组内是竞争关系，一条消息只会被组内的一个消费者处理）
    • last_delivered_id：游标，每个消费组均有这个游标，任意消费者读取均会使其向前移动
    • pending_ids：消费者的状态变量，维护消费者的已经读取未确认（XACK）的消息id
  • 模块（Modules）：Redis 支持动态加载模块，可以扩展 Redis 的功能

事务

  • redis事务一次可以执行多个命令，并带有下列三个保证：
    • 批量操作在发送exec命令前被放入队列缓存
    • 收到exec后进入命令执行，事务中任意命令执行失败，其他命令仍然被执行
    • 在事务执行过程中，其他客户端提交的命令请求不会被插到事务执行命令序列中

尽管redis的单个命令执行是原子性的， 但是redis事务并不是原子性的

  • discard取消事务，unwatch取消watch key [key...]的监视（当事务执行前这些key被其他命令修改，则事务被打断）

脚本

  • redis使用Lua解释器执行脚本，执行命令为eval

数据备份与恢复

  • save与bgsave（后台执行）在redis安装目录创建当前数据库备份
  • 恢复数据只需要将备份文件移动到redis安装目录下并启动服务即可
    • config get dir查询redis目录

管道技术

  • redis是基于CS模型的TCP服务，其意味着下一个请求会按照下列步骤：
    • 客户端发送查询请求，并监听socket返回，等待服务器响应
    • 服务器处理命令并返回结果
  • 管道技术，即：客户端可以在服务端未响应时，继续发送请求，并最终一次性读取所有服务端的响应
